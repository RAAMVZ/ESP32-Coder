01 / ПЕРВЫЙ ЗАПУСК

Установка — в отдельную папку

Рекомендуем скачивать ZIP-архив с папкой ESP32 Coder внутри. На странице последнего релиза GitHub выбирайте именно ZIP. Отдельный файл .exe в списке релиза предназначен для автоматического обновления. Не запускайте программу прямо из архива или временной папки: компоненты, кэш, настройки и проекты требуют постоянной папки с правом записи.
  1. Откройте последний релиз ESP32 Coder и скачайте ZIP-архив.
  2. Создайте постоянный каталог для программ, например C:\Dev\ (желательно без кириллицы и OneDrive).
  3. Распакуйте из ZIP папку ESP32 Coder целиком. В результате получится C:\Dev\ESP32 Coder\.
  4. Запускайте esp32coder.exe из этой папки. Сохраняйте каталог целиком при дальнейшей работе; отдельный EXE из GitHub Releases используйте только по назначению механизма автообновления.
C:\Dev\ESP32 Coder\
├── esp32coder.exe
├── runtime\          (компоненты)
├── Projects\
│   └── MyProject1\
│       ├── libs\
│       ├── MyProject1.cpp
│       └── esp32coder.ini
└── build_temp\       (возможна после сборки)

В обычном случае build_temp создаётся рядом с программой при сборке. Если путь содержит кириллицу или находится в OneDrive, Coder может перенести временную сборку в локальный каталог Windows.

Не рекомендуем Program Files без прав записи. Папка Projects создаётся программой автоматически.

02 / НАСТРОЙКА

Выберите плату и установите компоненты

  1. Запустите ESP32 Coder и в меню «Плата, порт» выберите вашу модель. Для примеров ниже — ESP32 Dev Module.
  2. Откройте «Компоненты» и установите предлагаемые для выбранной платы SDK/Arduino Core и toolchain. Набор зависит от семейства ESP32.
  3. При необходимости откройте «Библиотеки» и установите внешние библиотеки проекта.
  4. Подключите плату USB-кабелем с передачей данных и выберите её COM-порт.

ESP32 Coder работает без VPN: для локального редактирования, сборки и прошивки он не нужен. Первоначальная загрузка SDK, инструментов и библиотек требует интернета; после установки можно работать оффлайн.

03 / РОДНОЙ ФОРМАТ

Готовый проект ESP32 Coder

Демонстрационный ESP32_Smart_Monitor — проект с восемью исходными файлами: Wi-Fi точка доступа, HTTP-страница с JSON, чтение ADC и настройки через Preferences. Архив теперь содержит конфигурацию esp32coder.ini и каталог libs/ — это формат проекта Coder.

ESP32_Smart_Monitor/
├── libs/                ← библиотеки проекта
├── ESP32_Smart_Monitor.cpp
├── AppConfig.h
├── SensorHub.h
├── SensorHub.cpp
├── WebDashboard.h
├── WebDashboard.cpp
├── SettingsStore.h
├── SettingsStore.cpp
└── esp32coder.ini      ← настройки проекта

Coder создаёт папку проекта и каталог libs/, но не создаёт src/ и include/. Исходники и заголовки в этом примере лежат в корне проекта.

Вы можете использовать автоматическую очистку библиотек и в новом проекте: после успешной сборки Coder оставит в libs/ используемые библиотеки и их зависимости.

  1. Скачайте проект в формате ESP32 Coder ↓.
  2. Распакуйте папку ESP32_Smart_Monitor в C:\Dev\ESP32 Coder\Projects\ или другую постоянную папку проекта.
  3. В Coder выберите «Открыть» → «Открыть проект» и откройте ESP32_Smart_Monitor.
  4. Выберите ESP32 Dev Module и нажмите «Проверить» или «Собрать».
В примере используется вход ADC GPIO34, подходящий для классической ESP32 Dev Module. Для ESP32-S3/C3 и других плат измените номер вывода и проверьте аппаратную совместимость. Пример не проверен на реальной плате.

Что выводит монитор порта (115200 бод)

После запуска прошивка печатает сообщение о готовности. Далее при включённом журналировании примерно каждые 250 мс выводит измерение ADC на GPIO34 и сглаженное значение:

[SmartMonitor] System ready
ADC: 1.50 V | Avg: 1.50 V
ADC: 1.55 V | Avg: 1.51 V
ADC: 1.60 V | Avg: 1.52 V
ADC: 1.68 V | Avg: 1.54 V

Числа здесь рассчитаны по алгоритму SensorHub из примерных значений ADC. При подключении настоящей ESP32 они будут зависеть от напряжения на GPIO34. Программа не выводит Wi-Fi SSID, IP-адрес или HTTP-статус в Serial.

04 / ИМПОРТ ИЗ ARDUINO IDE

Как импортировать Arduino-скетч

ESP32 Coder импортирует папку проекта с главным файлом .ino, а не только содержимое открытого редактора.

Arduino_Blink_Serial/
├── Arduino_Blink_Serial.ino
└── BlinkConfig.h
#include <Arduino.h>
#include "BlinkConfig.h"

void setup() { Serial.begin(115200); pinMode(LED_PIN, OUTPUT); }
void loop() { digitalWrite(LED_PIN, HIGH); delay(500); digitalWrite(LED_PIN, LOW); delay(500); }
  1. Скачайте пример Arduino IDE ↓ и распакуйте его вне папки Coder Projects.
  2. В программе нажмите «Открыть» → «Импорт проекта Arduino IDE».
  3. Выберите папку Arduino_Blink_Serial (в ней лежит .ino).
  4. Укажите имя нового проекта и подтвердите импорт — он появится в Projects/.
  5. Проверьте плату, библиотеки, затем нажмите «Проверить» или «Собрать».
ESP32 Coder адаптирует Arduino-скетч к C++ и создаёт собственный esp32coder.ini. Оригинал из Arduino IDE остаётся на месте.

После импорта большого скетча удобно скопировать общие библиотеки Arduino IDE в libs/ и после успешной сборки автоматически удалить лишние. Аналогичная возможность есть и у новых проектов.

05 / ИМПОРТ ИЗ PLATFORMIO

Как импортировать проект PlatformIO

Для импорта выберите корневую папку проекта, где находится platformio.ini. Не выбирайте отдельно src/.

Структура ниже относится к исходному проекту PlatformIO, а не к проекту Coder:

PlatformIO_Blink_Serial/
├── platformio.ini
├── src/
│   └── main.cpp
└── include/
    └── BlinkConfig.h

После импорта в Coder исходники main.cpp и BlinkConfig.h располагаются в корне новой папки проекта; также создаются esp32coder.ini и libs/.

[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
monitor_speed = 115200
  1. Скачайте пример PlatformIO ↓ и распакуйте в отдельное место.
  2. Выберите «Открыть» → «Импорт проекта PlatformIO».
  3. Укажите папку PlatformIO_Blink_Serial с platformio.ini.
  4. Подтвердите имя проекта. Кодер перенесёт исходники, настройки платы и сведения о зависимостях в собственный проект.
  5. Проверьте выбранную плату и установленные библиотеки. Нажмите «Собрать».
platformio.ini используется для чтения параметров, но в проект Coder не копируется. Вместо него создаётся esp32coder.ini. Локальные библиотеки из lib/ и доступного кэша .pio/libdeps/ могут импортироваться в libs/; отсутствующие зависимости устанавливаются отдельно.
06 / БИБЛИОТЕКИ И ЗАВИСИМОСТИ

Импорт библиотек Arduino IDE в папку libs и автоматическая очистка

В ESP32 Coder библиотеки привязываются к конкретному проекту. Каждая внешняя библиотека хранится в своей подпапке libs/, рядом с исходниками и esp32coder.ini. Благодаря этому проект можно перенести на другой компьютер вместе с нужными библиотеками — их не придётся искать в общей папке Arduino IDE.

Особенно удобно при импорте больших Arduino-проектов. Можно сначала скопировать в libs/ библиотеки из общей папки Arduino IDE, а после первой успешной компиляции ESP32 Coder сам удалит из проекта библиотеки, которые не используются в текущем коде и не требуются зависимостями. Такой же подход работает и с новыми проектами Coder.

1. Как импортировать библиотеки

  1. Откройте или создайте проект в ESP32 Coder. Для импортированного Arduino-скетча сначала завершите импорт папки с главным .ino.
  2. Откройте менеджер «Библиотеки» и выберите импорт из папки библиотек Arduino IDE. В диалоге укажите общую папку, содержащую подпапки библиотек, например C:\Users\<пользователь>\Documents\Arduino\libraries. Если ваша Arduino IDE использует другое расположение, выберите его.
  3. Подтвердите импорт и дождитесь копирования. Coder переносит библиотеки в папку текущего проекта libs/, отображает ход копирования и не отсеивает их заранее по архитектуре ESP32.
  4. Откройте дерево проекта и проверьте содержимое libs/. При обычном копировании исходные папки библиотек Arduino IDE сохраняются без изменений.
Projects/
└── MyProject1/
    ├── MyProject1.cpp
    ├── esp32coder.ini
    └── libs/
        ├── ArduinoJson/
        ├── ESP_Async_WebServer/
        ├── Async_TCP/
        └── Some_Unused_Library/   ← пока тоже скопирована

Можно также добавлять отдельные библиотеки через менеджер, устанавливать их из GitHub (в русской версии доступен и поиск через Trema) или копировать папки непосредственно в libs/. Библиотеки, уже входящие в ESP32 Arduino Core, обычно отдельно копировать не нужно.

2. Что происходит после первой успешной сборки

  1. Выберите целевую плату и нажмите «Собрать» (или выполните полную «Проверить» с успешной компиляцией). Coder анализирует #include в исходниках, заголовки внешних библиотек и зависимости между библиотеками.
  2. Программа компилирует и компонует проект. Удаление запускается только после успешного завершения компиляции и компоновки, а для сборки — после создания BIN. При ошибке или отмене библиотеки не удаляются.
  3. Coder оставляет библиотеки, которые использует проект, а также библиотеки, необходимые им как зависимости. Излишние распознанные папки библиотек удаляются из локального каталога проекта (libs/; очистка также поддерживает проектные lib/ и .pio/libdeps/).
  4. В консоли появляется отчёт LIBRARY CLEANUP REPORT AFTER SUCCESSFUL VERIFY/BUILD с количеством проверенных, удалённых и сохранённых библиотек. При необходимости недостающую библиотеку можно снова импортировать или установить.
MyProject1/
├── MyProject1.cpp
├── esp32coder.ini
└── libs/
    ├── ArduinoJson/
    ├── ESP_Async_WebServer/
    └── Async_TCP/       ← нужная зависимость сохранена
Важно: это очистка библиотек проекта, а не кнопка очистки кэша компилятора. Если библиотека нужна лишь для другой платы, будущего кода, внешнего скрипта или подключается нестандартно без обычного #include, автоматический анализ может не распознать её. Храните резервную копию таких библиотек вне libs/ перед первой успешной сборкой. Из общей папки Arduino IDE при обычном импорте ничего не удаляется.

3. Тот же механизм для нового проекта

  1. Создайте новый проект, например MyProject2: Coder создаст его папку и libs/.
  2. Добавьте необходимые или потенциально нужные библиотеки через «Библиотеки» либо скопируйте их из своего каталога.
  3. Напишите код с нужными #include и выполните первую успешную сборку.
  4. Просмотрите отчёт об очистке: останутся используемые библиотеки и их зависимости, лишние папки будут удалены.

Если после этого добавите в проект новый модуль или #include, просто установите недостающую библиотеку в libs/ и соберите снова. Это позволяет содержать проект компактным и не засорять его общим набором Arduino-библиотек.

07 / РАБОТА С ПЛАТОЙ

Проверка, сборка, прошивка

Проверить

Проверка проекта и зависимостей без прошивки.

Собрать

Компиляция и создание файла прошивки BIN.

Загрузить

Сборка и прошивка через выбранный COM-порт.

Для диагностики используйте «Монитор и плоттер»; скорость порта должна совпадать с Serial.begin(...), в примерах — 115200.

08 / СОВЕТЫ

Если что-то не получается

Нет SDK или toolchain

Выберите нужную плату и откройте «Компоненты». Дождитесь установки для соответствующего семейства ESP32 и повторите сборку.

Импорт не видит .ino или platformio.ini

Выбирайте корневую папку: для Arduino — каталог с главным .ino, для PlatformIO — каталог с platformio.ini.

Нет COM-порта

Проверьте USB-кабель, драйвер USB-UART и не занят ли порт другим монитором. После подключения обновите список портов.

Не сохраняются проекты или кэш

Убедитесь, что программа распакована и запущена из отдельной папки, доступной для записи, а не из ZIP или временной папки.
