Get started without a complex setup

A practical guide to first launch, native ESP32 Coder projects, and importing Arduino IDE and PlatformIO projects.

01 / INSTALLATION

Run from a dedicated folder

We recommend downloading the ZIP archive containing the ESP32 Coder folder. On the latest GitHub release page, choose the ZIP file. The separate .exe release asset is intended for automatic updates. Never run the app directly from the archive or a temporary directory: components, caches, projects, and settings need a permanent writable folder.
  1. Open the latest ESP32 Coder release and download the ZIP archive.
  2. Create a permanent parent folder, such as C:\Dev\, preferably outside OneDrive.
  3. Extract the complete ESP32 Coder folder from the ZIP into it. The app will be at C:\Dev\ESP32 Coder\.
  4. Run esp32coder.exe from that folder. Keep the entire working directory together; the standalone EXE release asset is reserved for the automatic update workflow.
C:\Dev\ESP32 Coder\
├── esp32coder.exe
├── runtime\          (components)
├── Projects\
│   └── MyProject1\
│       ├── libs\
│       ├── MyProject1.cpp
│       └── esp32coder.ini
└── build_temp\       (may be created on build)

The build_temp directory is normally created alongside the app when building. For Unicode or OneDrive paths, Coder may relocate temporary build files to a local Windows directory.

Avoid Program Files unless the directory is writable. ESP32 Coder creates Projects automatically.

02 / CONFIGURATION

Select a board and install components

  1. Launch ESP32 Coder and choose your board from Board / Port. Use ESP32 Dev Module for the examples.
  2. Open Components and install the required SDK/Arduino Core and toolchain for the selected board.
  3. If required, open Libraries and install any missing external dependencies.
  4. Connect your board using a data-capable USB cable and select its COM port.

An internet connection is needed for the initial component download. Once installed, local editing, compilation and flashing can work offline.

03 / NATIVE PROJECT

Open a native ESP32 Coder example

The ESP32_Smart_Monitor example contains eight source files for a Wi-Fi access point, a small HTTP/JSON status endpoint, ADC sampling, and Preferences-based settings. Its ZIP now includes esp32coder.ini and libs/, which make it a native Coder project.

ESP32_Smart_Monitor/
├── libs/                ← project-local libraries
├── ESP32_Smart_Monitor.cpp
├── AppConfig.h
├── SensorHub.h
├── SensorHub.cpp
├── WebDashboard.h
├── WebDashboard.cpp
├── SettingsStore.h
├── SettingsStore.cpp
└── esp32coder.ini      ← project configuration

Coder creates the project folder and libs/, but not src/ or include/. The source and header files in this example sit directly in the project root.

  1. Download the native ESP32 Coder project ↓.
  2. Extract ESP32_Smart_Monitor into C:\Dev\ESP32 Coder\Projects\ or another permanent workspace.
  3. In Coder, choose Open → Open project and select ESP32_Smart_Monitor.
  4. Select ESP32 Dev Module and choose Check or Build.
The example uses ADC input GPIO34 on a classic ESP32 Dev Module. Change the pin for ESP32-S3/C3 and other boards; verify hardware compatibility. Hardware testing of this example has not been performed.

Expected Serial Monitor output (115200 baud)

The firmware prints a ready message on startup. With logging enabled (the default), every 250 ms it prints the ADC voltage on GPIO34 and the exponentially filtered average:

[SmartMonitor] System ready
ADC: 1.50 V | Avg: 1.50 V
ADC: 1.55 V | Avg: 1.51 V
ADC: 1.60 V | Avg: 1.52 V
ADC: 1.68 V | Avg: 1.54 V

These numbers are calculated from illustrative ADC input values using the SensorHub algorithm. On an actual ESP32 they depend on GPIO34 voltage. This example does not print Wi-Fi SSID, IP address, or HTTP status over Serial.

04 / ARDUINO IDE IMPORT

Import an Arduino sketch

ESP32 Coder imports the whole sketch folder containing the main .ino file, rather than just an editor selection.

Arduino_Blink_Serial/
├── Arduino_Blink_Serial.ino
└── BlinkConfig.h
#include <Arduino.h>
#include "BlinkConfig.h"

void setup() { Serial.begin(115200); pinMode(LED_PIN, OUTPUT); }
void loop() { digitalWrite(LED_PIN, HIGH); delay(500); digitalWrite(LED_PIN, LOW); delay(500); }
  1. Download the Arduino import example ↓ and extract it outside Coder's Projects directory.
  2. Choose Open → Import Arduino IDE project.
  3. Select the Arduino_Blink_Serial folder containing the .ino file.
  4. Set a new project name and confirm. The imported project appears under Projects/.
  5. Confirm the board and dependencies, then choose Check or Build.
Coder adapts Arduino sketch sources for C++ compilation and creates a native esp32coder.ini. Your Arduino IDE original is left unchanged.
05 / PLATFORMIO IMPORT

Import a PlatformIO project

Select the root project folder containing platformio.ini, not src/ by itself.

This is the original PlatformIO layout, not the resulting Coder project:

PlatformIO_Blink_Serial/
├── platformio.ini
├── src/
│   └── main.cpp
└── include/
    └── BlinkConfig.h

After importing into Coder, main.cpp and BlinkConfig.h are placed in the new project root; Coder also creates esp32coder.ini and libs/.

[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
monitor_speed = 115200
  1. Download the PlatformIO import example ↓ and extract it outside the Coder workspace.
  2. Choose Open → Import PlatformIO project.
  3. Select the PlatformIO_Blink_Serial folder with platformio.ini.
  4. Confirm the new name. Coder copies source files, compatible board settings and dependency information into a native project.
  5. Confirm the board and libraries, then choose Build.
platformio.ini is read for settings but is not copied into the Coder project. Coder creates esp32coder.ini instead. Local lib/ libraries and available .pio/libdeps/ caches may be copied into libs/; install any missing libraries separately.
06 / DEPENDENCIES

Libraries per project

Each project has its own libs/ folder. Use Libraries to find and install libraries from GitHub, import or update dependencies, or copy libraries from your Arduino IDE's shared library directory. Dependency analysis helps identify which libraries your project needs.

The sample projects above use libraries supplied by the ESP32 Arduino Core and need no extra third-party packages.

07 / DEVICE WORKFLOW

Check, build and flash

Check

Inspect project configuration and dependencies without flashing.

Build

Compile and generate a firmware BIN.

Upload

Build and flash using the selected COM port.

For debugging, open Serial Monitor and Plotter. Match its baud rate to Serial.begin(...); these examples use 115200.

08 / TROUBLESHOOTING

Common questions

SDK or toolchain missing

Select your target board and open Components. Install the correct package for that ESP32 family, then retry the build.

Importer cannot find .ino or platformio.ini

Select the project root: a folder containing the main .ino for Arduino IDE or platformio.ini for PlatformIO.

COM port missing

Check the USB cable, USB-UART driver and whether another serial monitor has claimed the port. Refresh the port list.

Projects or cache do not persist

Run the unpacked application from a dedicated writable folder, never from the ZIP or a temporary archive directory.
